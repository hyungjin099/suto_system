# 작업 인수인계 (다른 PC에서 이어서 작업용)

> 작성 시점: 2026-10-21 / 기준 커밋: `37c8da9` (main)
> 이 문서는 한 번의 채팅 세션에서 진행한 분석·수정 내역과 남은 일을 정리한 것이다.

---

## 1. 프로젝트 개요

- **스택**: Spring Boot 3.5 / Java 17 / MyBatis / MariaDB + React(Vite) 프론트(`src/front_dream_company`)
- **역할 분리** (자세한 설계: `시스템_재설계_명세서.md`, `알림기능_명세서.md`)
  - 시스템 = 주문 **접수 레이어**. DB 저장 후 Google Sheets(Apps Script 웹훅)에 push.
  - 스프레드시트 = 공장이 자유롭게 쓰는 영역. 수정/삭제/분할/완료 체크는 시트에서 수동.
- **흐름**
  ```
  주문 접수 → OrderService.submitOrder (DB 저장)
    ├ 18시 이전 → SheetsWebhookService.push → Apps Script doPost → "오늘_" 시트
    └ 18시 이후 → STATUS=DEFERRED → 다음 영업일 02:00 DeferredPushJob이 push
  SheetsRetryJob: 5분마다 PENDING/FAILED(24시간 이내) 재전송
  시트 트리거: 00시 오늘 탭 생성 → 01시 미완료 이월 → (02시 Spring DeferredPush)
  ```
- **접수 차단**: 주말, 공휴일, 23:00~03:00 (`OrderAvailabilityService`). 관리자는 예외.
- **웹훅 URL**: 반기별(H1/H2)로 `SYSTEM_SETTING` 테이블에 저장. 공휴일은 Apps Script가 단일 소스(Spring이 `action:"holidays"`로 조회, 00:30 캐시 갱신).

## 2. 저장소 구조 (이번에 추가된 것)

```
apps_script/
  code.gs        # 시트 연동 메인 (웹훅, 트리거, 공휴일, 이월, 오늘 탭)
  재단취합.gs     # 재단취합 시트 기능
docs/작업_인수인계.md   # 이 문서
```

- `.gs` 파일은 **git에 올려도 Google 시트에 자동 반영되지 않는다.** 수정 후 Apps Script 에디터에 직접 붙여넣어야 한다. (자동화하려면 `clasp` 도입 가능 — 미도입)
- `apps_script/code.gs`는 인증키가 코드에서 제거된 버전이다 (아래 4번).

## 3. 이번 세션에서 한 일

### 3.1 코드 분석에서 찾은 문제 → 수정 완료

| # | 문제 | 수정 |
|---|---|---|
| 1 | Apps Script는 오류가 나도 **HTTP 200 + `{"status":"ERROR"}`** 로 응답하는데, Java `push()`가 HTTP 2xx만 보고 성공 처리 → 시트에 못 쓰고도 주문이 `OK`로 기록되어 영영 유실 | `SheetsWebhookService.push`: body의 `status == "OK"`까지 확인. JSON이 아닌 응답(로그인 HTML 등)도 실패 처리 |
| 2 | `DeferredPushJob`(02시)이 토·일만 확인하고 공휴일은 확인 안 함 | `HolidayService.isHoliday`도 확인해 비영업일이면 skip (DEFERRED 유지) |
| 3 | 프론트 안내 문구가 "00~01시 점검"으로 낡음 (서버는 23~03시 차단) | `OrderForm.jsx` `tryReview`: 23:00~03:00 기준으로 변경 |
| 4 | 공휴일 갱신이 시트의 수동 임시공휴일을 매일 지움, API 한 해만 실패해도 그 해 데이터 삭제, 00시 트리거 간 순서 경쟁 | `refreshHolidays` 병합 방식으로 재작성 (아래 3.2) |
| 5 | 코드에 공공데이터 인증키 평문 | 스크립트 속성으로 분리 (아래 4번) |

### 3.2 공휴일 갱신 방식 (code.gs)

공휴일 시트: 3행부터, `B=날짜(yyyy-MM-dd)`, `C=이름`, `D=갱신시각`.

- **D열이 비어 있으면 "수동 입력"** → 자동 갱신이 지우지 않는다. 같은 날짜가 API에도 있으면 API 행만 남김(중복 제거).
- API 조회에 **성공한 해**: 그 해의 기존 API 행을 새 결과로 교체.
- API 조회에 **실패한 해**: 기존 행 유지. 두 해 모두 실패하면 시트를 건드리지 않고 중단.
- `getHolidayFromAPI`: 실패 → `null`, 성공(공휴일 없음 포함) → 배열.
- `refreshHolidays` 트리거: **00시 → 23시**로 변경 (00시 탭 생성 전에 최신화).
- `onEdit`: 공휴일 시트를 직접 고치면 `_holidayCache`를 비움.

### 3.3 검증한 것 / 하지 않은 것

- 검증함: `./gradlew compileJava` 통과, `.gs` 두 파일 `node --check` 문법 통과, 공휴일 병합 로직을 Apps Script 객체를 가짜로 대체한 Node 모의 테스트(수동 보존 / 중복 제거 / API 제거분 삭제 / 실패 연도 유지 / 전체 실패 시 무변경)로 확인.
- **검증 못 함**: 실제 Google Sheets·Apps Script 환경에서의 동작, 프론트 화면, 서버 기동 후 통합 동작.

## 4. 인증키 분리 (시트 적용 시 필수)

- 코드에서 `SERVICE_KEY` 상수를 제거. 스크립트 속성 `HOLIDAY_SERVICE_KEY`에서 읽는다 (`getServiceKey_()`).
- 메뉴 `주문관리 → 🔑 공공데이터 인증키 설정`으로 입력하면 저장된다.
- 키가 없으면 공휴일 갱신이 "인증키가 설정되지 않았습니다" 오류로 멈춘다.
- 인증키 값 자체는 이 저장소·히스토리 어디에도 없다. 필요하면 공공데이터포털에서 확인/재발급.
- 만료 예정일은 `CONFIG.HOLIDAY_API.KEY_EXPIRY = '2027-11-05'` (60일 전부터 메일 알림).

## 5. 이어서 해야 할 일

### 5.1 반드시 (배포/적용)

1. **Spring 배포** — `SheetsWebhookService`, `DeferredPushJob` 변경 반영. 프론트(`OrderForm.jsx`)도 빌드·배포.
2. **Apps Script 반영** — 수정된 `apps_script/code.gs`, `apps_script/재단취합.gs`를 시트의 Apps Script 에디터에 붙여넣기.
3. 시트 새로고침 후 **`🔑 공공데이터 인증키 설정`** 으로 키 입력 (건너뛰면 공휴일 갱신 실패).
4. 메뉴 **`🚨 초기 설정: 트리거 등록`** 재실행 (공휴일 갱신이 23시로 바뀜. 기존 트리거는 전부 삭제 후 재생성됨).
5. 메뉴 **`공휴일 갱신`** 수동 실행으로 시트가 채워지는지 확인. 공휴일 시트에 수동 임시공휴일(D열 비움) 하나 넣어 보존되는지도 확인.
6. 새 반기 파일이 복사되면 스크립트 속성(인증키)이 같이 복사되는지 확인 — 안 되면 새 파일에서 키 재설정.

### 5.2 확인 필요 (동작 변화)

- 시트 쓰기 실패가 이제 `FAILED`로 남는다. 관리자가 **휴일에 전화 주문**을 넣으면 시트에 못 쓰고 `FAILED` → `SheetsRetryJob`이 24시간 동안 5분마다 재시도 후 `FAILED`로 남는다(다음 영업일 자동 이월 안 됨). 관리자 화면에서 `FAILED`가 보이면 수동 조치 필요. 이 정책을 바꿀지 결정할 것.
- Apps Script 웹앱 배포 권한이 어긋나 HTML을 돌려주면 모든 주문이 `FAILED`가 된다 (의도된 감지).
- 수동 임시공휴일은 Spring `HolidayService`에 **다음 00:30 갱신 때** 반영된다. 그 전에는 고객 접수 차단이 모른다. 즉시 반영이 필요하면 공휴일 시트 `onEdit`에서 Spring에 알리는 방식 검토.

### 5.3 의도적으로 보류한 항목

- **이월 중복 실행**: 같은 날 이월을 두 번 돌리면 중복된다 (이월 후 어제 시트 R열을 `이월됨`으로 덮어써서 중복 체크가 깨짐). 같은 날 두 번 실행하는 경우가 없다고 판단해 보류.
- **고객 비밀번호 서버 미강제**: `login`이 세션/토큰을 만들지 않고 `/api/orders`, `/orders`, `/fabrics`(단가 포함)가 인증 없이 열려 있다. `cliCode`만 알면 주문·내역 조회 가능. 일단 패스로 결정.

### 5.4 미해결 후보 (선택)

- **서버 시간대 의존**: `OrderService`의 `ORDER_DATE`와 `SheetsWebhookService.buildPayload`의 `orderDate`는 `LocalDateTime.now()`(서버 기본 시간대). DEFER 판정·주문번호는 KST. 서버가 UTC면 시트의 발주일/납기/배경색이 9시간 어긋남. 운영 서버 시간대가 KST인지 확인하거나 `LocalDateTime.now(KST)`로 통일.
- Apps Script의 `_formatSheetName`은 `date.getDay()`를 쓴다 → Apps Script 프로젝트 시간대가 `Asia/Seoul`이어야 함.
- `OrderItemVo`에 `deliveryDate` 필드가 없어 거래처 주문 내역 응답에서 납기 override가 조용히 누락됨 (관리자 화면은 별도 DTO라 영향 없음).
- 낡은 주석: `buildPayload`의 "시트 P열 매칭용"(실제 R열), `schema.sql`의 `ORDER_ID` 주석 `'ORD-XXXXXX'`(실제 `YYYYMMDD-NNN`).
- `.gs` 자동 배포: `clasp` 도입 검토.

## 6. 참고 사실 (헷갈리기 쉬운 것)

- DEFER 기준은 **18시** (최근 커밋에서 17→18로 변경, `OrderService.DEFER_PUSH_HOUR`). 시트의 파란 배경은 14:00~17:59 접수분(`getRowColorByHour`).
- 02시 Spring `DeferredPushJob`은 Apps Script의 공휴일 검사를 거치지 않는다 — 그래서 Java 쪽에서도 `HolidayService`로 판단한다. 01시 이월은 Apps Script 안에서 `isHoliday`를 확인한다.
- 시트 쓰기 중복 방지는 R열 `itemNum`으로 **오늘 시트 안에서만** 확인한다.
- 재단취합은 `오늘_` 시트만 읽으며, 분할 자식 행의 R열에 `부모번호-N` 형태의 가상 itemNum을 써 넣는다.

## 7. 다른 PC에서 시작하기

```bash
git pull origin main
./gradlew compileJava          # 백엔드 컴파일 확인
cd src/front_dream_company && npm install   # 프론트 의존성
```

- 백엔드 환경변수: `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `SHEETS_WEBHOOK_URL`(초기 seed용), `ALLOWED_ORIGINS`, `COOKIE_SECURE`. 기본값은 `application.properties` 참고.
- 프론트: `.env.example`을 복사해 `VITE_API_BASE_URL` 설정.
